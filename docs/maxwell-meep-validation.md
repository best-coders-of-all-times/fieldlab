# Offline native Meep validation

The checked-in fixture was generated by **native Meep 1.35.0**, Python 3.11.17,
the conda-forge `nompi` build under Ubuntu 24.04 in WSL. This is an optional,
isolated reference toolchain in `.reference-tools/meep`; the browser application
does not load Python, Meep, or reference fixtures.

## Reproduce

From the repository root on Windows PowerShell:

```powershell
wsl -d Ubuntu-24.04 -- bash scripts/setup-meep-reference.sh
wsl -d Ubuntu-24.04 -- .reference-tools/meep/bin/python scripts/meep-reference.py
node scripts/check-meep-reference.mjs
```

The first command installs the optional toolchain locally and requires network
access. On Linux, run the shell script and Python executable directly. The Python
generator writes `tests/fixtures/maxwell/meep-periodic.json`; `--output PATH`
selects another destination. The Node checker uses Vite's server module loader
to instantiate the actual `src/engine/maxwell/yee.ts` CPU kernel, then steps it
and compares its fields with the checked-in native data. Checking the fixture
requires the project's existing Node dependencies and no native tools or
network. `--report PATH` also saves the numerical comparison report as JSON.

## Equivalent configuration

Both solvers use a one-dimensional, length-one periodic cell, no impressed
sources, no objects, no conductivity, and relative permeability one. Separate
cases use uniform relative permittivity one and four. Resolutions are 32, 64,
and 128 cells. The Courant number is 0.5, `dz=1/N`, and the reference timestep
is `dt=0.5/N`. The final time is 0.25 for every case; snapshots are stored at
steps 0, N/4, and N/2. The CPU grid is `nx=ny=1, nz=N`, with periodic boundaries
on all axes. Transverse differences are therefore zero.

Meep's dimensionless convention sets `c=epsilon_0=mu_0=1`. Here its length unit
is one metre and its time unit is `1/299792458` seconds. The arbitrary electric
amplitude is one V/m. Thus `E_SI=E_Meep`, `B_SI=B_Meep/c`, and
`dt_SI=dt_Meep/c`; relative material values agree directly. This conversion is
explicit in the fixture and checker. See [Meep's units and Courant convention](https://meep.readthedocs.io/en/latest/Introduction/#units-in-meep).

For this polarization, `Ex` is sampled at `z_i=-0.5+i*dz` and `By` at
`z_i+dz/2`. The generator discovers and checks these native positions from
Meep's initialization callbacks. It samples each component at its own native
locations with `get_field_point`, avoiding the spatial averaging of ordinary
field-array output. The coordinates are saved in the fixture. See
[Meep's Yee lattice](https://meep.readthedocs.io/en/latest/Yee_Lattice/).

Both solvers store E at `t` and raw B at `t-dt/2`. Each snapshot saves raw By
and By synchronized to the E time. Meep uses
`synchronize_magnetic_fields()` followed by `restore_magnetic_fields()`;
the CPU comparison uses `YeeSolver.synchronizedB(1,i)`. Synchronization
averages the adjacent half-step fields and has second-order temporal accuracy.
See [Meep's synchronization documentation](https://meep.readthedocs.io/en/latest/Synchronizing_the_Magnetic_and_Electric_Fields/).

## Initial condition and continuum comparison

The smooth standing-wave mode has wavenumber `k=2*pi`. For each resolution let

```text
theta = 2*asin((0.5/sqrt(epsilon))*sin(k*dz/2))
Ex(z,0) = cos(k*z)
By(z,-dt/2) = -sqrt(epsilon)*sin(k*z)*sin(theta/2)
```

This supplies the correct half-step magnetic initial condition for the discrete
mode; starting B at zero would introduce a first-order phase offset. Both
solvers receive the same independently evaluated formulas. Meep initializes
`Dx=epsilon*Ex` and By so its constitutive E/H fields are initialized too, as
specified by [Meep 1.35.0's initialization implementation](https://github.com/NanoComp/meep/blob/v1.35.0/src/initialize.cpp).

The continuum target is evaluated separately:

```text
omega = k/sqrt(epsilon)
Ex(z,t) = cos(k*z)*cos(omega*t)
By(z,t) = sqrt(epsilon)*sin(k*z)*sin(omega*t)
```

The chosen half-step initialization converges to this physical initial state
with second-order accuracy. The fixture's field samples come from actual
native timestepping, not from either analytic formula or the application's
kernel. The generator asserts its initial field samples and timestep before
running Meep.

## Measured results

The following results were reproduced on 2026-10-24. The maximum CPU/Meep
error is the largest spatial RMS across Ex, raw By, synchronized By, and all
three snapshots. Magnetic errors are divided by `sqrt(epsilon)` to use the
same unit amplitude convention as the electric error.

Regeneration produced byte-identical fixture data (SHA-256
`964a0571cd70a2874a416a2578b61683695c519e7721701a1802f52648c2ffea`).
A failure-path check changed one stored magnetic sample by 0.01, confirmed that
the checker rejected it, restored the original bytes, and reran the passing
comparison.

| Medium | N | Max CPU/Meep RMS | Continuum RMS at t=0.25 | Refinement ratio |
| --- | ---: | ---: | ---: | ---: |
| Vacuum | 32 | 1.87e-16 | 1.121829981e-3 | — |
| Vacuum | 64 | 1.94e-16 | 2.804356292e-4 | 4.00031 |
| Vacuum | 128 | 2.51e-16 | 7.010753547e-5 | 4.00008 |
| epsilon_r=4 | 32 | 1.08e-16 | 6.704976938e-4 | — |
| epsilon_r=4 | 64 | 1.53e-16 | 1.677065429e-4 | 3.99804 |
| epsilon_r=4 | 128 | 2.44e-16 | 4.193176972e-5 | 3.99951 |

Continuum RMS is `sqrt((mean(E_error^2)+mean(B_error^2)/epsilon)/2)`
using synchronized B. The checker requires CPU/Meep RMS below `1e-10`,
continuum RMS below 0.01, and each refinement ratio between 3.8 and 4.2.
These thresholds allow platform roundoff while requiring second-order
convergence; they are not a claimed accuracy bound for arbitrary scenes.

This comparison validates a smooth, source-free transverse mode, material wave
speed, periodic indexing, SI scaling, and magnetic time alignment. It does not
validate PML, PEC walls, material interfaces, conductivity, longitudinal charge,
moving sources, three-dimensional geometry, worker integration, or rendering.
Those require their own analytic or application tests. A matched Yee scheme
can agree to roundoff with Meep while retaining finite continuum dispersion,
which is why the refinement results are reported separately.
